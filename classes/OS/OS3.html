Process scheduling

Executable Programs

An executable is a specially formatted file that contains all the information the operating system needs to properly load and run a program in memory. It includes the starting instruction, memory relocations, required libraries, and other metadata.

  • Starting instruction - The entry point where execution begins.
  • Relocations - Information about how addresses should be adjusted when loading into memory.
  • Libraries - External code modules required by the program to run.
  • Executable formats - Different OSes use different formats:
    • Portable Executable (PE) - Windows (.exe)
    • Executable and Linkable Format (ELF) - Linux
    • Mach Object (MachO) - Mac

Process States

When a program is loaded into memory, it becomes a process that is ready to run. Processes can exist in several different states depending on what they are currently doing:

  • New - The program has just been loaded into memory and is being initialized. It is preparing to enter the ready state.
  • Ready - The process is prepared to execute but is waiting for the CPU to schedule it. It has all resources except the CPU.
  • Running - The process is currently executing instructions on the CPU.
  • Blocked - The process cannot continue until some event occurs, such as completion of an I/O operation or availability of a resource.
  • Terminated - The process has finished execution and is removed from the system. All resources are released.

Process Needs

A process requires several resources to execute properly and interact with the system:

  • CPU - Time on the processor to execute instructions.
  • Memory - Storage for the process's code, data, and current state.
  • I/O Devices - Access to files, storage devices, or input/output hardware.
  • Network Access - Ability to send and receive data over a network if needed.
  • Interprocess Communication - Mechanisms to send messages and coordinate with other processes.

Process Memory

A process's memory is divided into several regions, each with a specific purpose:

  • User Stack - Stores static data and function call information. Allocated at compile time.
  • Heap - Dynamic memory allocations during runtime, typically via malloc or similar functions.
  • Read/Write (RW) Area
    • .data - Stores initialized variables.
    • .bss - Stores uninitialized variables.
  • Read-Only (RO) Area
    • .txt - Contains executable code.
    • .rodata - Stores constants, strings, and jump tables.
    • .init - Initialization routines.
  • Shared Libraries - Code shared across multiple processes to save memory and allow updates without recompiling.

Operating System Challenges

Operating systems have to manage a variety of tasks to ensure that programs run efficiently and safely. Some key challenges include:

  • Create Processes - The OS must load a program into memory, initialize its resources, and set it up to run as a process.
  • Suspend & Resume Processes - The OS should be able to pause a running process (e.g., waiting for I/O) and later resume it without losing its state.
  • Terminate Processes - After a process finishes execution or needs to be stopped, the OS must safely release its resources and remove it from the system.

Process Information

The operating system keeps track of each process in order to manage them effectively. This includes storing a variety of details for every process:

  • Process ID - A unique identifier, usually an integer.
  • Command line arguments - Parameters passed to the program when it starts.
  • Memory allocated - Memory reserved for the process to use.
  • Open files - Files currently being used by the process.
  • Permissions - Access rights for files, devices, and other resources.
  • Parent & Child Process(es) - Relationships between processes.
  • Loaded libraries - External code that the process depends on.
  • ...and other relevant details

All of this information for a single process is stored in a structure commonly called a process descriptor.

Windows PCB & PEB

In Windows, the process control block (PCB) is known as the EPROCESS structure. It contains all the information the OS needs to manage a process, including its state, memory usage, and resource handles. Kernel space structures like EPROCESS are not directly accessible to user-mode applications for security and stability reasons. Information needed for scheduler, dispatcher, and interrupt accounting is stored in the KPROCESS structure, which is embedded within the EPROCESS structure. Fields: Context Switches, Affinity, Priority, Process State, etc.

The PEB (Process Environment Block) is another important structure that holds information about the process's environment, such as loaded modules and environment variables. User space applications can access the PEB to retrieve information about their own process. Used by heap manager, image loader, and other subsystems. Fields: Thread local storage, Heap pointer, Loaded modules, etc.

Tracking Processes

The operating system maintains a list of all active processes, often referred to as the process table. This table allows the OS to quickly find and manage processes as needed. Each entry in the process table corresponds to a process descriptor (like EPROCESS in Windows or task_struct in Linux). The OS uses this table to schedule processes, allocate resources, and handle interprocess communication.

Doubly linked list is commonly used to implement the process table, allowing efficient insertion and deletion of processes. Each process descriptor contains pointers to the next and previous processes in the list, enabling quick traversal

Hash Tables can also be used for faster lookups based on process IDs or other attributes. This allows the OS to quickly find a process descriptor without having to traverse the entire list. Use Pid as a lookup entry to find the process descriptor in the hash table. Why does this work? Because Pid is unique to each process.
